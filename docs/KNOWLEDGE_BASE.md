# Regionwright project reference

This path remains the stable project-reference location used by the synchronized knowledge record. The pre-split knowledge base and its older project rules are preserved in the [workspace retirement archive](../archives/regionwright-workspace-retirement-20261018.zip).

## Current source of truth

- [Project Standards](PROJECT_STANDARDS.md) defines the active project-wide product and source rules.
- [Module Strategy](EDITION_STRATEGY.md) records module ownership, compatibility, installation evidence, archives, and the current handoff.
- [Studio module plan](STUDIO_MODULE_PLAN.md) records Studio scope and future composition work.
- [Puzzles & Locks module plan](PUZZLES_LOCKS_MODULE_PLAN.md) records puzzle ownership, API, and migration compatibility.
- [Puzzles & Locks artwork references](../art-source/regionwright-puzzles-locks/puzzle-artwork/README.md) records the four supplied static artwork references, their Cabin puzzle mappings, and remaining art-preparation gaps.
- [Cabin in the Ashen Veil implementation handoff](CABIN_ASHEN_VEIL_REGIONWRIGHT_IMPLEMENTATION_HANDOFF_2026-10-24.md) preserves the owner-provided planning context and its distinction between approved reference art and implemented or playtested puzzles.
- [Hunting & Gathering module README](../modules/regionwright-hunting-gathering/README.md) records that package's setup and behavior.
- [Visual Art Direction Roadmap](ART_DIRECTION_ROADMAP.md) records the planned human-authored point-cloud style across all modules, including future refinement of the existing lock puzzles.

Campaign-specific research, maps, macros, and the knowledge database remain separate from the reusable module catalog. They may call the documented Studio compatibility alias while being migrated to module-specific APIs.
